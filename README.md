# Psy By Agent - Финальное ТЗ (MVP)

## 1. Цель проекта
Создать веб-приложение для анализа и интерпретации снов с использованием локальной LLM.

Пользовательский сценарий:
- пользователь заходит на главную страницу;
- регистрируется или авторизуется;
- попадает в интерфейс с историей обсуждений снов и чат-окном;
- описывает сон и ведет диалог с ИИ-ассистентом;
- завершает обсуждение, после чего в БД сохраняются история диалога и итоговая интерпретация.

## 2. Технологический стек

### 2.1 Backend
- Java 17
- Spring Boot 3
- Gradle
- Spring Web
- Spring Security
- Spring Data JPA
- Bean Validation
- Lombok
- Flyway
- PostgreSQL JDBC Driver

### 2.2 Frontend
- JavaScript
- React (рекомендуется, Vite)

### 2.3 Инфраструктура
- PostgreSQL в локальном Docker
- Ollama локально на машине разработчика
- Модель: Qwen (через Ollama)

## 3. Общая архитектура
- Frontend взаимодействует только с Backend API.
- Backend:
  - обрабатывает аутентификацию/авторизацию;
  - хранит пользователей, сессии снов и сообщения в PostgreSQL;
  - отправляет запросы в Ollama/Qwen;
  - возвращает ответы модели во Frontend.
- Все данные пользователя изолированы: пользователь видит только свои сессии и сообщения.

## 4. Роли и учетные записи
- Роль `USER`: основной пользователь приложения.
- Роль `ADMIN`: техническая/тестовая роль.
- Тестовый пользователь создается автоматически при старте приложения (если отсутствует):
  - логин: `admin`
  - пароль: `admin`

## 5. Функциональные требования

### 5.1 Главная страница
- Отображает действия:
  - `Войти`
  - `Зарегистрироваться`

### 5.2 Регистрация
- Пользователь вводит логин и пароль.
- Логин должен быть уникальным.
- Пароль сохраняется в БД только в хешированном виде.

### 5.3 Авторизация
- Вход по логину/паролю.
- После успешного входа пользователь переходит на страницу чата.

### 5.4 Экран после авторизации
- Левая панель:
  - список сессий снов пользователя;
  - по нажатию на сессию открывается ее история.
- Центральная область:
  - окно переписки;
  - ввод сообщения;
  - отправка сообщения.
- Действия:
  - `Новый сон` (создает новую сессию);
  - `Завершить обсуждение` (закрывает текущую сессию);
  - `Выйти`.

### 5.5 Чат и анализ сна
- Пользователь отправляет сообщение с описанием сна или уточнениями.
- Backend передает контекст диалога в Ollama с моделью Qwen.
- Ответ модели сохраняется в БД и показывается пользователю.
- Общение идет в рамках выбранной сессии сна.

### 5.6 Завершение обсуждения
- При завершении сессии:
  - статус сессии меняется на `COMPLETED`;
  - формируется и сохраняется итоговая интерпретация сна в поле `final_interpretation`;
  - история сообщений остается доступной для просмотра.

## 6. Нефункциональные требования
- Приложение должно запускаться локально у разработчика.
- Backend API защищен: приватные endpoints доступны только авторизованным пользователям.
- Обязательная обработка ошибок:
  - недоступность PostgreSQL;
  - недоступность Ollama;
  - невалидные входные данные;
  - отсутствие доступа к чужим данным.
- Логирование ключевых действий и ошибок на стороне backend.

## 7. Модель данных (PostgreSQL)

### 7.1 Таблица `users`
- `id` (PK)
- `username` (unique, not null)
- `password_hash` (not null)
- `role` (not null)
- `created_at` (not null)

### 7.2 Таблица `dream_sessions`
- `id` (PK)
- `user_id` (FK -> users.id, not null)
- `title` (not null)
- `status` (`ACTIVE` / `COMPLETED`, not null)
- `final_interpretation` (text, nullable до завершения)
- `created_at` (not null)
- `updated_at` (not null)

### 7.3 Таблица `dream_messages`
- `id` (PK)
- `session_id` (FK -> dream_sessions.id, not null)
- `sender` (`USER` / `ASSISTANT`, not null)
- `content` (text, not null)
- `created_at` (not null)

## 8. Миграции БД
- Использовать Flyway.
- Первая миграция: создание всех таблиц, индексов и ограничений (`V1__init.sql`).
- Последующие изменения схемы только через новые миграции.

## 9. API (MVP-контракт)

### 9.1 Auth
- `POST /api/auth/register` - регистрация.
- `POST /api/auth/login` - авторизация.

### 9.2 Dream sessions
- `GET /api/dreams` - получить список сессий текущего пользователя.
- `POST /api/dreams` - создать новую сессию сна.
- `GET /api/dreams/{id}` - получить конкретную сессию и ее сообщения.

### 9.3 Messages and completion
- `POST /api/dreams/{id}/messages` - отправить сообщение в сессию, получить ответ ИИ.
- `POST /api/dreams/{id}/complete` - завершить сессию и сохранить итоговую интерпретацию.

## 10. Интеграция с Ollama/Qwen
- Backend использует локальный endpoint Ollama (по умолчанию `http://localhost:11434`).
- Для ответов ассистента используется установленная локально модель Qwen.
- Промпт должен учитывать контекст текущей сессии сна и историю сообщений.

## 11. Безопасность
- Хранить пароли только в хешированном виде (например, BCrypt).
- Доступ к данным строго по владельцу сессии (`user_id`).
- Не возвращать чувствительные внутренние данные в API-ответах.

## 12. Критерии приемки MVP
1. Пользователь может зарегистрироваться и войти в систему.
2. Тестовый пользователь `admin/admin` доступен после запуска backend.
3. После авторизации доступен экран с историей снов и чат-интерфейсом.
4. Можно создать сессию сна, отправить сообщение и получить ответ от локального Qwen через Ollama.
5. История диалога сохраняется в PostgreSQL и доступна после повторного входа.
6. Можно завершить обсуждение, итоговая интерпретация сохраняется в `final_interpretation`.
7. Миграции Flyway применяются автоматически при старте backend.

## 13. Границы MVP
В MVP не входят:
- расширенная ролевая модель и админ-панель;
- сложная аналитика пользователя;
- экспорт в PDF/документы;
- мультиязычность интерфейса;
- потоковая (streaming) генерация токенов в UI.

## 14. Следующий этап после утверждения

## 16. Локальный запуск (первый инкремент)

### 16.1 PostgreSQL
```bash
docker compose up -d
```

### 16.2 Ollama и модель
```bash
ollama pull qwen2.5:7b
ollama run qwen2.5:7b
```

### 16.3 Backend
В каталоге `backend`:
```bash
./gradlew bootRun
```
Если wrapper еще не создан, можно использовать локальный Gradle:
```bash
gradle bootRun
```

Backend URL: `http://localhost:8080`

### 16.4 Frontend
В каталоге `frontend`:
```bash
npm install
npm run dev
```

Frontend URL: `http://localhost:5173`

## 18. Переменные окружения

### 18.1 Backend (`backend/src/main/resources/application.yml`)
Можно переопределять значения через env:
- `SERVER_PORT` (по умолчанию `8080`)
- `SPRING_DATASOURCE_URL` (по умолчанию `jdbc:postgresql://localhost:5432/psy_db`)
- `SPRING_DATASOURCE_USERNAME` (по умолчанию `psy_user`)
- `SPRING_DATASOURCE_PASSWORD` (по умолчанию `psy_pass`)
- `APP_JWT_SECRET`
- `APP_JWT_EXPIRATION_MS` (по умолчанию `86400000`)
- `APP_OLLAMA_BASE_URL` (по умолчанию `http://localhost:11434`)
- `APP_OLLAMA_MODEL` (по умолчанию `qwen2.5:7b`)

### 18.2 Frontend
Создай файл `.env` в каталоге `frontend` на основе `frontend/.env.example`:
```bash
VITE_API_BASE_URL=http://localhost:8080/api
```
